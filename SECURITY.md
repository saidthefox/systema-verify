# Security policy

## Reporting a vulnerability

Do not disclose credentials, private keys, unpublished record material, personal identifiers, or a
working exploit in a public issue.

Use GitHub private vulnerability reporting for this repository. Include the affected verifier
version, the smallest reproducible record or manifest, expected and observed behavior, and whether
the issue could make an invalid record appear verified or a valid record appear failed.

If private vulnerability reporting is unavailable, contact the repository owner through an
established private channel and reference this policy without publishing exploit details.

## Scope

High-priority reports include signature bypasses, incorrect replay, ruleset substitution, checkpoint
confusion, artifact-hash bypasses, and unsafe handling of remote record content. A disagreement with
an accepted ontology claim is not a verifier vulnerability.
